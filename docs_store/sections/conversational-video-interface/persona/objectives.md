Objectives
Objectives are goal-oriented instructions to define the desired outcomes and flow of your conversations. Objectives work alongside your system prompt to provide a structured, flexible approach to guide conversations. They provide the most value during purposeful conversations that need to be tailored to specific processes, customer journeys, or workflows, while maintaining engaging and natural interactions. For example, if you're creating a lead qualification persona for sales, you can set objectives to gather contact information, understand budget requirements, and assess decision-making authority before scheduling a follow-up meeting. Objectives can only be created using the Create Objectives API.
When designing your objectives: Plan your entire ideal workflow. This helps create a robust branching structure. Think through the possible answers a participant might give, and ensure the workflow covers these cases. Ensure your persona's system prompt does not conflict with the objectives.
Attaching objectives to a persona. Add them during persona creation:
curl --request POST --url https://tavusapi.com/v2/personas/ --header 'x-api-key: <api-key>' --data '{"system_prompt": "You are a lead qualification assistant.", "objectives_id": "o12345"}'
OR add them by editing the persona:
curl --request PATCH --url https://tavusapi.com/v2/personas/{persona_id} --header 'x-api-key: <api-key>' --data '[{"op": "add", "path": "/objectives_id", "value": "o12345"}]'
objective_name: A descriptive name for the objective. Example: "check_patient_status". Must be a string value without spaces.
objective_prompt: A text prompt that explains what the goals of this objective are. Example: "Ask the patient if they are new or are returning."
confirmation_mode: Defines whether the LLM should determine whether this objective was completed. If auto, the LLM makes this decision. If manual, the participant must manually confirm via app message (conversation.objective.pending) and send one back (conversation.objective.confirm). Default is auto.
output_variables (optional): A list of string variables that should be collected as a result of the objective being successfully completed. Example: ["patient_status", "patient_group"]
modality: Whether a specific objective should be completed based on the participant's verbal or visual responses. Each objective can be visual or verbal (not both). Default is "verbal".
next_conditional_objectives: A mapping of objectives (by objective_name) to conditions that must be satisfied for that objective to be triggered after the completion of the current objective. Mutually exclusive with next_required_objective. Example: {"new_patient_intake_process": "If the patient has never been to the practice before", "existing_patient_intake_process": "If the patient has been to the practice before"}
next_required_objective: The name of the next required objective that will be activated once the current objective is completed. Mutually exclusive with next_conditional_objectives. Example: "get_patient_name"
callback_url (optional): A URL to send notifications to when a particular objective has been completed. The callback payload includes conversation_id, the objective name, and any collected output variables: {"conversation_id": "<conversation_id>", "objective_name": "<objective_name>", "output_variables": {"<variable_name>": "<value>"}}
