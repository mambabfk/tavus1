Memories
Memories let personas remember information across conversations, allowing participants to have personalized, flowing conversations across multiple sessions. Memories are pieces of information that the persona learns during a conversation; once learned, they can be referenced and used in subsequent conversations. Developers organize memories within memory_stores — a flexible tag-based system to track memories across conversations and participants into different buckets.
If a memory_stores value is provided in the conversation creation request, memories are automatically created and associated to the tag provided. When defining memory_stores values, incorporate static values that will not change with persona updates, like persona ID. (Using a persona's name could cause miscategorization if the name changes.)
Basic Example: if a participant named Anna starts a conversation with the persona (Charlie, persona ID p123), specify memory_stores=["anna_p123"] in the conversation creation request. Charlie will then remember what was mentioned and form new memories with Anna, and reference memories from previous conversations with Anna. Example body: {"persona_id": "your_persona_id", "replica_id": "your_replica_id", "memory_stores": ["anna_p123"]}.
Managing Memories Between Participants and Conversations: to prevent different personas from mixing up information for the same participant, create separate memory_stores values per user per persona. When Anna talks to Charlie (p123) use ["anna-p123"]; when she talks with Gloria (p456) use ["anna-p456"]. memory_stores do not have to map 1:1 with participants — e.g. an online classroom could use "classroom-1" so any participant of the group can reference and create shared memories. Control whether personas share memory by passing them the same or different memory_stores values.
Delete a memory: delete a single memory via the API using the same memory_store value used when creating the conversation and the memory ID. curl -X DELETE "https://tavusapi.com/v2/memories/<memory_store>/<memory_id>" -H "x-api-key: YOUR_API_KEY". Replace <memory_store> (e.g. anna_p123) and <memory_id> with the ID of the memory to delete.
