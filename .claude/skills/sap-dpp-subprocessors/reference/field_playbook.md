# Field playbook — SAP DPP Subprocessors Details v1.1

Bucket A = researchable from vendor primary sources.
Bucket B = Tavus program answer, uniform across all columns, from config.
Bucket C = human sign-off required; agent proposes with reasoning only.

Exact allowed dropdown strings live in `form_spec.json`. Use them verbatim.

| Row | ID | Field | Bucket | Where to look / rule |
|---|---|---|---|---|
| 3 | 1.1 | Legal name + legal form | A | Vendor DPA signature block or corporate registry. Must match the entity named in the TOM questionnaire #8.3 Tavus already submitted — check that file first, it overrides research. |
| 4 | 1.1.1 | Full address + Art. 27 EU representative | A | DPA or privacy policy. Art. 27 rep only exists for non-EU vendors targeting EU subjects; absence is a legitimate finding, not a gap to fill. |
| 5 | 1.1.2 | DPO name, phone, email | A | Privacy policy "contact us" section. Most US vendors have no formal DPO — then the form requires `N/A` here *and* a working privacy contact in the 1.1.1 column. Do not invent a name. |
| 6 | 1.1.3 | Processing operations description | C | Draft from the vendor's role in the Tavus data flow. Must state which categories of personal data and to what extent. This is the cell SAP's reviewers read most closely. |
| 7 | 1.1.4 | Level (1 = direct, 2 = vendor's vendor) | B | From `scope.yaml`. Note: Cerebrium/Replicate/Fal run on AWS/GCP, so those hyperscalers are arguably Level 1 *and* Level 2. Flag, don't guess. |
| 8 | 1.2 | Mirror sub-processing DPAs in place? | B | Yes/No. Config only. |
| 9 | 1.3 | Did they actually implement the TOM? | B | Yes/No. Config only. |
